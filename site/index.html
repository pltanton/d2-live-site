D2 · state machines · any editor · Claude Code

Draw it. Watch the code change.

d2-live keeps a diagram open next to your work and redraws it the moment the .d2 file changes — whether you, your editor or your agent wrote it. Press E and the picture becomes editable: click a state, rename it, wire a transition, and the file changes by exactly those lines.

Install GitHub

state 01

Point at it, see its code

Click a state or a transition and its declaration lights up in the code panel, with every other mention dimmer. Put the cursor on a line and the diagram answers back. A diagram of forty states stops being a scavenger hunt.

then

state 02

Change it on the diagram

Rename a state and every transition follows. Switch its class from a menu that shows the colours. Hit →, click the target, type the event — a transition. Click empty canvas instead and you get a new state already wired in. Each change flashes in the code as a diff, and ⌘Z takes it back.

or

state 03

Or just type

The code panel is a real editor. The preview renders what you type, not what is saved, so half a line never lands in the file — ⌘S writes it. While the code does not compile, the last good picture stays and the error sits under the line that caused it.

meanwhile

state 04

Your editor and your agent keep the pen

The file is the only source of truth. Edits from Helix, a git checkout or Claude Code stream into the open tab and flash where they landed. If one races your unsaved typing, you choose: take theirs or keep yours.

Under the hood

Small, fast, and polite to your files

Diffs a human would write

Edits are byte-level splices on the D2 syntax tree, not a reformat. Renaming a state touches its declaration and the transitions that mention it — nothing else moves.

@@ -14 +14 @@
-PAYMENT_CAPTURED: {class: active}
+PAID: {class: active}
 SHIPPED: {class: active}
@@ -24 +24 @@
-PAYMENT_PENDING -> PAYMENT_CAPTURED: "payment: CAPTURED" {class: evt}
+PAYMENT_PENDING -> PAID: "payment: CAPTURED" {class: evt}

Fast where it matters

Layout and rendering run in-process with a warm ELK, so a redraw is a fraction of a second, and panning moves a ready picture instead of repainting every label.

One server, every diagram

The first d2-live becomes the server; later calls just add files to it. Point it at a directory and every *.d2 lands in the tab's file list. Layout engine and sketch mode switch in place.

d2-live docs/diagrams

Opens from your editor

Attach d2-live --lsp as a language server: opening a .d2 file opens its preview, closing the editor stops the server. No keybindings.

[language-server.d2-live]
command = "d2-live"
args = ["--lsp"]

Install

With Nix

The flake builds the binary; SVG rendering is built in, PNG export uses the d2 CLI if you have it.

nix profile install github:pltanton/d2-live

Then:

d2-live diagram.d2

For Claude Code

The plugin teaches Claude to register the diagrams it writes and hand you the preview link instead of re-running the server after every edit.

/plugin marketplace add pltanton/d2-live
/plugin install d2-live

The recordings run the real d2-live in a browser driven by a script, so every take is the same. Cursor and key badges are drawn on top for the video.
